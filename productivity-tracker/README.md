# Productivity Tracker — тестирование

Объект тестирования: [productivity-tracker](https://github.com/golubev21312-afk/productivity-tracker) — веб-приложение для учёта активностей, целей и анализа продуктивности (React + Node.js/Express + PostgreSQL).

**Что проверялось:** регистрация и вход, работа с токеном, активности, цели, «Анализ дня», доступ к чужим данным, ответы API при ошибках, целостность данных в БД.

**Окружение:** локальный стенд, коммит `116cc83`, Node.js 22, PostgreSQL 16, Chromium. Дата: 31.10.2026.

## Итоги

| Показатель | Значение |
|---|---|
| Проверок в чек-листе | 38 (20 пройдено, 18 с багами) |
| Найдено багов | **13**: 1 critical, 7 major, 3 minor, 2 trivial |
| Автотестов (Playwright) | 47: 40 API + 7 UI. 29 проверяют рабочую логику, 18 фиксируют баги |
| Запросов в Postman-коллекции | 13, в них 17 проверок |
| SQL-проверок данных | 10 |

**Главное, что найдено:**
- По инструкции из README приложение не запускается: регистрация и вход падают с 500 из-за отсутствующей переменной окружения ([BUG-001](bug-reports.md#bug-001)).
- Через `PUT` можно переписать владельца записи и подкинуть свои активности и цели в чужой аккаунт ([BUG-012](bug-reports.md#bug-012)).
- На один email можно завести два аккаунта, если поменять регистр букв ([BUG-003](bug-reports.md#bug-003)).
- API принимает время `25:99` и любую строку вместо даты — это портит статистику, а часть записей не видна в интерфейсе ([BUG-005](bug-reports.md#bug-005), [BUG-006](bug-reports.md#bug-006)).

**Что работает хорошо:** чужую запись нельзя прочитать, изменить или удалить по её id (ответ `404`), API без токена недоступен, сообщение при неверном входе не раскрывает, существует ли такой email.
